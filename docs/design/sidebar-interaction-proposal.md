# 左侧栏交互重设计方案

状态：**方案，尚未实现**。本轮仅提供交互方案和演示原型，不改变应用行为。原型中的 Gamma 数值为演示值，不代表读取到的显示器参数。

用户已明确要求「只识别，手动决定」。因此新用户默认采用**识别辅助**：识别软件并展示建议，用户主动使用才应用滤镜。**自动跟随**作为用户明确开启的可选模式保留。升级不得擅自改变已有模式：原来自动启用且未暂停的用户保留自动；原来关闭或暂停的用户进入识别辅助并保留输出。

名称与迁移：方案中的常用默认滤镜统一命名为「通用滤镜」。实现时按原滤镜的稳定 ID 定向更新显示名称，保留该条目的 ID、参数、软件分配和显示器偏好引用，不新建替代条目，不批量改写其他同名滤镜。本轮文档与原型不会修改已有用户配置。

视觉方向：采用 Windows 桌面工具的中性灰阶。取消紫色、渐变、大圆角和卡片式状态块；状态改为紧凑信息行，管理入口采用列表操作。正文使用 Segoe UI / Microsoft YaHei，主要确认按钮用灰阶，少量低饱和蓝色仅用于已应用标记和输入控件。警告状态保留文字与警告色，明暗外观均保持中性。该视觉偏好同时适用于两种布局。

## 推荐：状态优先

左侧按「目标显示器 → 当前已应用 → 工作模式 → 软件识别与建议 → 未设置软件的默认建议 → 单独软件设置 → 底部管理入口」排列。滤镜库通过弹层打开，不在主侧栏常驻显示列表。

```text
显示器                         [刷新]
[S65 · Screen 1                  ▾]
2560 × 1440 · 320 Hz · 主显示器

当前已应用
通用滤镜 · 用户选择
输出：驱动 LUT 读回一致

工作模式（全部显示器）
[ 识别辅助 ] [ 自动跟随 ]

当前识别：QQ · 最近外部软件
建议：通用滤镜 · 未设置软件的默认
[使用建议滤镜]

未设置软件建议（S65）
[通用滤镜                       ▾]
[单独软件设置…]

────────────────────────────────
[滤镜库…]
[编辑当前]      [从当前新建]
```

**识别、建议、已应用是三个不同状态。** 例如识别到 CS2，建议 cs2，但用户尚未点击使用时，「当前已应用」仍显示之前使用的通用滤镜；不能把建议写成生效结果。建议与已应用参数相同时标明「已使用此建议」，避免重复写入。

滤镜库弹层保留用户现有名称（包括 `Default`）；浏览、选中滤镜不应用、不改模式。明确的「手动使用」操作才应用所选滤镜，进入识别辅助并保持人工选择。自动模式中该操作标明「手动使用，转为识别辅助」。显示「最近外部软件」时必须注明，不能把正在前台的 Gamma Changer 称作 QQ。

## 核心状态与操作规则

| 对象／动作 | 规定行为 |
|---|---|
| 当前识别 | 记录最近外部前台软件、窗口、exe、查询结果和快照序号；切软件只更新识别。GUI 取得焦点时保留最近外部软件信息并标明。 |
| 当前建议 | 按「完整 exe 路径＋该显示器的专属规则 → 本屏未设置默认」解析；未知软件建议通用滤镜等用户选定默认，不猜测它属于游戏还是浏览器。建议不是已应用状态。 |
| 当前已应用 | 保存最后一次应用的滤镜、参数、来源和输出确认状态；不能用编辑选中项或建议替代。API 成功只表示写入调用报告成功；驱动 LUT 读回一致也不证明游戏最终画面符合滤镜。首次启动没有本工具已应用记录时如实注明。 |
| 识别辅助（默认） | 软件切换、规则保存、默认建议更改、识别失败和低频复查均只更新识别／建议，不写 LUT；保持用户上次主动应用的输出。启动程序也不自动应用记忆滤镜。 |
| 使用建议滤镜 | 点击时捕获建议的快照序号、软件身份、显示器和参数版本，应用前再次核对；已过期则更新建议并提示重新选择，不应用旧建议。确认成功后更新已应用状态。 |
| 手动使用 | 在滤镜库选择明确的滤镜后主动应用；转为识别辅助，外部软件改变只刷新建议。该动作是用户主动改变输出，不由浏览列表触发。 |
| 自动跟随（可选） | 用户明确开启后，按最新外部软件与各屏默认自动解析并应用。全局模式在控件旁标明；每屏分别保存规则、默认及人工应用记录。模式变更明确保存。 |
| 转为识别辅助 | 停止自动应用，保留当前输出，不恢复桌面 LUT。之后识别变化仅影响建议。 |
| 打开主界面／切显示器 | 只查看状态和编辑上下文，不恢复桌面 LUT、不应用记忆滤镜、不改模式。单纯打开 GUI 不能触发输出变化。 |
| 未设置默认 | 主界面直接选择已有滤镜，每屏保存。识别辅助下只影响之后的建议；自动跟随下按最新软件重算。完整产品继续支持高级配置中的「沿用桌面设置」，指本屏保存的桌面基准，本轮原型未演示。保留 `Default` 名字，其中性参数不称作物理原始色彩。 |
| 编辑滤镜 | 创建独立草稿，默认不预览；明确「保存」「取消」「临时预览」。修改共享滤镜时展示引用数量。识别辅助下保存参数不自动应用，包括保存当前使用的滤镜；标明已保存的新参数尚未应用，主动使用后才更新输出。 |
| 临时预览 | 用户主动开启，标明目标屏、预览滤镜和临时状态，不改规则或模式。识别辅助下切软件只更新建议，不借焦点事件写入或恢复 LUT。用户明确结束预览／取消编辑时恢复预览前人工应用的输出；若已有后续主动应用，则不能用旧快照覆盖它。 |
| 保存／取消编辑 | 没有预览时，识别辅助只重算最新建议、输出不变；自动跟随按最新软件和规则重算应用。已开启临时预览时，结束该预览是独立的输出恢复步骤：识别辅助恢复预览前输出，自动跟随解析最新软件，不能把取消当成应用新建议。 |
| 新建 | 「从当前新建」复制本屏最近确认的已应用参数为草稿，编辑名称后创建；创建不应用、不改模式。成功后打开滤镜库并选中新项，标「未使用」，提供「手动使用」。输出未确认时禁用从当前复制，仍可复制明确的已有滤镜。 |
| 删除 | 行菜单展示规则、每屏默认和人工应用记录的引用，用户选择替代项后一次保存。识别辅助下替换引用只更新配置／建议，不改变当前输出；已删除但仍在输出中的参数注明为保留的人工效果，下一次主动使用才替换。自动跟随则按最新规则重算。取消无修改。 |

滤镜配置和当前人工输出分开保存，避免修改或删除配置时隐式改变屏幕。首次安装的桌面基准明确初始化并保存，此后只在用户主动操作时更新。任何输出未确认时，不提供声称复制真实当前效果的操作。

滤镜库的「生效」标记同时核对滤镜 ID 和已应用参数。修改参数但尚未主动使用时，标「旧参数／修改未应用」，不能把新配置标成当前输出。

## 单独软件设置：一个入口，一个保存边界

主界面仅保留「单独软件设置…」，替换 `Bind app…`／`App rules…`，打开软件管理器。识别辅助和自动跟随均保留这个入口。最近外部软件在管理器内部标记，不增加主侧栏快捷按钮；标记不自动创建规则或应用滤镜。

管理器主要内容为「软件 → 滤镜 → 显示器」，每个软件和显示器有一个明确的专属分配，所有修改显式保存。识别辅助保存后只更新建议；自动跟随保存后按最新软件重算。添加、修改、删除分配均不切换模式。旧多条规则必须保留并展示实际优先的一条，迁移不能静默丢失配置。

「添加应用」是规则草稿中的选择应用子步骤：

1. 直接列出有窗口的运行应用，展示应用名称、窗口标题和完整 exe 路径；按 exe 分组，可展开其他窗口。提供搜索、刷新、手动浏览。
2. 选应用后回到同一个分配草稿，选择已有滤镜，默认显示当前查看的显示器。返回列表、刷新或取消应用选择，不丢掉已填的滤镜和显示器。
3. 保存草稿才写规则；取消整个编辑无修改。识别失败项注明 Windows 原因，允许手动浏览 exe 设置规则，但不能承诺之后可以自动读取它。

不要以「Set as default」表示软件分配，使用「此软件建议滤镜」。每屏未设置默认单独命名。自动跟随仍使用这些相同规则，但不把保存规则解释为开启自动。

## 智能识别规划

用户要求的智能识别是**识别辅助，手动决定**。以下能力尚未实现；本期按 Windows 软件身份识别并展示规则建议，不推测任意软件类别，不承诺识别网页画面。

### 身份与匹配

维护前台快照：窗口句柄、PID、完整 exe 路径、可执行名、窗口标题、查询错误和版本序号。窗口标题用于列表展示，不替代身份。完整 exe 路径＋显示器的启用专属规则优先；没有规则时给本屏默认建议。

完整路径归一化大小写／斜杠。更新后路径变化，默认视作未设置，不静默改写绑定。按可执行名回退属于用户显式启用的高级规则，只有目标分配唯一且无路径冲突时使用。两套同名 exe 有不同分配时显示歧义、建议本屏默认；识别辅助中仍不改变输出。读取失败不能拿窗口标题假装已经识别。

### 事件为主，低频复查

保留前台事件和约 100–150ms 合并，增加约 500–1000ms 的低频前台复查。只在身份变化、显示恢复或有限重试时重新解析；识别辅助中复查没有 LUT 写入权限。Hook 注册失败提示使用轮询，不直接关闭识别。

采集结果及用户点击建议时核对窗口、PID、快照序号、显示器和参数版本，过期结果丢弃；连续 Alt+Tab 只保留最新建议。GUI 聚焦保留最近外部软件。前台瞬间为 NULL 时等待稳定；持续无外部前台显示「暂无外部前台，默认建议：通用滤镜」，不猜测后台游戏。前台恢复后重算建议。可选自动跟随按同一最新状态应用。

### 权限、游戏与浏览器边界

- **权限：**保留最小进程查询权限与错误码。无权限时显示「无法读取软件身份」和默认建议，识别辅助保持已应用输出。提升权限只作为用户主动选择的诊断手段，不保证解决反作弊或受保护进程限制。
- **游戏：**分配实际运行游戏的 exe，不把 Steam／Epic 启动器规则继承给所有游戏。分别验证窗口游戏、独占全屏、显示模式切换。识别成功与滤镜输出可用是不同结果。
- **浏览器：**本期按浏览器 exe 建议，同一浏览器标签页共用软件规则，标题只作展示。未来按网站功能另行设计用户授权的浏览器扩展与活动标签页域名通信；扩展未连接退回浏览器软件建议，不读取或猜测网页内容。此功能不改变默认的手动决定原则。

### 输出验证

只有用户主动使用、临时预览及明确开启的自动跟随可以改变输出。主动写入后读回驱动 LUT，将错误、不一致与 HDR 兼容性单独展示，有限重试，不无限写入争抢。

Microsoft 说明 `SetDeviceGammaRamp` 可能返回成功但未设置，其他程序可覆盖 LUT，显示变化可重置它，HDR 行为未定义。读回最多验证驱动报告的 LUT，不能等同真实游戏画面或永久有效。见 [Microsoft SetDeviceGammaRamp 文档](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-setdevicegammaramp)。

识别失败、匹配失败与应用失败不得混同。用户主动应用失败时标「输出未确认」，保留最后一次已确认记录及失败目标，禁用从当前复制／编辑当前效果；仍可编辑已有滤镜和软件规则。重试当前建议也必须再次核对快照。无法从任意 LUT 唯一推导六项滤镜参数。

## 备选：软件优先

采用「显示器 → 工作模式 → 软件分配／滤镜库页面切换 → 底部小型已应用状态」。软件分配页面显示软件对应的建议规则及未设置默认；滤镜库页用于浏览和编辑。建议操作显式触发，两个模式及保存规则与推荐方案一致。

```text
显示器
[S65 · Screen 1                  ▾]
工作模式（全部显示器）
[ 识别辅助 ] [ 自动跟随 ]

[ 软件分配 ] [ 滤镜库 ]
Chrome                 通用滤镜
CS2                    cs2
未设置软件             通用滤镜
[＋ 添加应用]

当前识别：CS2
建议：cs2
[使用建议滤镜]

────────────────────────────────
已应用：通用滤镜 · 用户选择
输出：驱动 LUT 读回一致
```

优点是软件分配更直接；代价是当前已应用状态不如推荐方案突出。推荐采用状态优先，软件管理器采用软件优先列表。

## 本轮原型验证

已在浏览器中验证：保存 QQ → cs2 分配仅更新建议；主动使用才更新已应用状态；修改未设置默认不改变人工效果；保存当前滤镜的新 Gamma 后，复制当前效果仍取旧参数；删除当前滤镜后保留人工快照；「添加应用」直接展示运行列表。主侧栏及应用选择弹层在 320px 宽度下的控件均无横向越界。以上仅验证演示原型，不能代替原生程序的识别及 LUT 验收。
