# 2.6.1 release review

Reviewed on 2026-10-11 against `e6a8b6b9c6453c19cdb320cee853e12356e7de63` (2.6.0).

## Standards

No release-blocking standards violations found. Domain rule matching remains independent
of Win32; process handles and foreground hooks are released; fallback configuration
retains compatibility with previous rule formats and atomic writes.

## Spec

Two behavior gaps were found and fixed:

- Re-enabling an existing disabled assignment now enables switching and resumes after
  the outer Save action. Cancel preserves the previous configuration and pause state.
- Editing the parameters of an enabled software filter selects it as the application's
  default and resumes after saving. Editing a disabled filter keeps it disabled.

The native regression fixture covers both gaps using actual dialogs, including two
competing rules for the same executable and display. All display writes use a fake backend.

The sidebar redesign and recognition assistance are explicitly future work. Release notes
do not claim they are implemented in this version.

## Release workflow

Four issues were fixed: release tags are read from the environment and validated;
upload/edit/create failures stop the job; reruns preserve published releases; invalid
signature states fail instead of being labeled unsigned. Six offline stub scenarios passed.

## Verification

Final Windows x64 Release and Debug builds passed with `/W4 /WX`. All five CTest groups
passed in both configurations (10/10). `git diff --check` and PowerShell script syntax
checks also passed. The release is built from its reviewed tag by GitHub Actions; publication waits
for CI and the release job to succeed, and for downloaded checksums and ZIP contents to
match the standalone executable.
